# 서울 공공도서관 빈자리 레이더

브라우저에서 공공데이터포털 API 인증키를 노출하지 않도록 Node.js 서버가 API를 대신 호출합니다. 서버는 시작 직후 다섯 구의 좌석·도서관 API를 조회하고, 이후 매시 00·05·10·15분 등 고정된 5분 경계마다 스냅샷을 갱신합니다. 예를 들어 1시 42분에 시작하면 42분에 먼저 조회하고 45분에 다시 조회합니다. 브라우저는 서버에서 가장 최근 스냅샷을 읽습니다.

## 준비

- Node.js 18 이상
- 공공데이터포털 API 활용 신청 및 인증키

`.env.example`을 `.env`로 복사하고 `DATA_GO_KR_SERVICE_KEY`에 공공데이터포털의 **Decoding 인증키**를 입력하세요. `.env`는 `.gitignore`에 포함되어 있어 저장소에 올라가지 않습니다.

PowerShell 예시:

```powershell
Copy-Item .env.example .env
notepad .env
node .\server.mjs
```

브라우저에서 `http://127.0.0.1:3000`을 열면 됩니다. 서버를 외부에 배포할 때는 `HOST=0.0.0.0`과 배포 플랫폼의 비밀 환경변수 설정을 사용하세요. 인증키를 HTML이나 공개된 설정 파일에 넣지 마세요.

## 동작

- 기본 지자체 코드는 강남구 `1168000000`입니다.
- `GET /api/seats?stdgCds=1168000000,1121500000,1162000000,1126000000,1130500000`은 서버가 정기 갱신으로 저장한 자치구 스냅샷을 하나로 합쳐 반환합니다. `stdgCd` 단일 파라미터도 계속 지원합니다. 이 경로는 공공 API를 직접 호출하지 않습니다.
- API 응답의 `body.item`을 도서관별로 묶어 화면에 표시합니다.
- 좌석 수는 `남은 좌석 · 전체 좌석` 순으로 보여줍니다. 같은 시각에 전체·이용·잔여 좌석 수가 똑같이 내려온 열람실은 API 좌석값이 동일하다고 표시하고 도서관 합계에서는 한 번만 계산합니다.
- 층 정보는 열람실명, 좌석 API의 층 값, 도서관 주소 순으로 보완하며 `1F` 같은 표기는 `1층`으로 통일합니다. 원본과 주소 모두 층 정보를 주지 않는 경우에는 `층 정보 없음`으로 표시합니다.
- 서버는 시작 직후 다섯 구의 스냅샷을 먼저 채우고, 이후에는 매시 00·05·10·15분 등 5분 경계에 맞춰 갱신합니다. 따라서 서버가 절전에서 깨어나거나 재시작된 뒤 다음 경계까지 기다릴 필요가 없습니다. 브라우저는 서버 캐시만 읽으므로 브라우저 새로고침은 공공 API 호출을 늘리지 않습니다.
- 결과가 없으면 빈 결과로 표시하고, API 오류는 페이지 상태에 표시합니다.
- 로컬 HTML 파일을 직접 열지 말고 Node 서버 주소로 접속해야 합니다.


## 지도와 거리

- 목록/지도 버튼으로 보기를 전환합니다.
- 기본 기준점은 서울특별시청입니다. `내 위치로 거리 계산`을 누르고 브라우저 위치 권한을 허용하면 현재 위치를 기준으로 바뀝니다. 권한 거부나 위치 오류 시 시청 기준으로 돌아갑니다.
- 위치 좌표는 브라우저 안에서만 사용하며 API 서버로 보내지 않습니다. 위치 기능은 HTTPS 또는 localhost에서 동작합니다.
- 거리는 도로 경로가 아닌 두 좌표 사이의 직선거리입니다. 현재 좌표는 논현·대치·도곡정보문화도서관에 등록되어 있으며, 다른 API 도서관은 좌표를 추가할 때까지 지도에서 별도 안내합니다.
- 지도는 Leaflet과 OpenStreetMap 타일을 사용하고 지도 안에 저작자 표시를 둡니다. 지도 타일은 인터넷 연결이 필요합니다.

## 서울 서비스 지역

현재 API 응답에서 열람실 정보가 확인된 지역 중 강남구청 기준으로 가까운 네 곳을 강남구와 함께 제공합니다.

- 강남구 (1168000000)
- 광진구 (1121500000)
- 관악구 (1162000000)
- 중랑구 (1126000000)
- 강북구 (1130500000)

정기 갱신 한 번에 다섯 구의 좌석 API와 통합정보 API를 각각 조회합니다. 한 페이지 응답 기준으로 5분 경계당 10회, 하루 약 2,880회이며 시작 직후 조회가 더해져도 통상 2,890회 이내입니다. 페이지가 나뉘면 페이지마다 API 호출이 추가되므로 서버는 한국 시간 기준 하루 4,500회에서 추가 호출을 중단해 5,000회 한도에 여유를 둡니다. 이 안전 카운터는 실행 중인 서버 프로세스 안에서 관리되므로 동일한 인증키를 여러 서버/배포본에서 함께 쓰거나 하루 중 서버 프로세스를 반복 재시작하면 호출량이 합산되지 않을 수 있습니다. 그런 운영에서는 공유되는 영속 저장소 기반의 호출량 관리가 필요합니다. Render 무료 웹 서비스가 절전 상태에서 다시 시작되면 즉시 스냅샷을 채운 뒤 5분 경계 갱신을 재개합니다.

지도 좌표는 도서관 ID만으로 연결하지 않고 자치구 코드와 도서관 ID 조합으로 구분합니다. 도서관 통합정보 API의 lat(위도), lot(경도)와 도로명 주소를 좌석 정보의 자치구 코드 및 도서관 ID에 연결해 지도 위치와 거리를 표시합니다.

## Render에 공개 배포하기

1. GitHub에 새 저장소를 만들고 `outputs` 폴더 안의 파일을 저장소 루트에 올립니다. `.env`는 절대 올리지 말고 `.gitignore` 설정을 유지하세요.
2. Render에서 **New → Blueprint**를 선택해 GitHub 저장소를 연결하고 `render.yaml`을 적용합니다.
3. 배포 중 `DATA_GO_KR_SERVICE_KEY` 입력란에 공공데이터포털의 Decoding 키를 직접 입력합니다. 키는 Render 환경변수로 보관되고 저장소에는 포함되지 않습니다.
4. 배포가 끝나면 Render가 제공한 `https://….onrender.com` 주소로 접속합니다. 지도와 위치 기능을 포함해 HTTPS로 열립니다.

이 저장소에는 Render 설정(`render.yaml`)과 시작 명령(`package.json`)이 준비되어 있습니다. 무료 웹 서비스는 15분 동안 요청이 없으면 잠들 수 있고, 다시 접속할 때 시작 시간이 걸릴 수 있습니다. 계속 켜진 실서비스가 필요하면 유료 인스턴스를 선택하세요.
